# 导入截图性能优化方案

## 问题分析

根据日志，导入40张截图耗时 **138636ms (约2.3分钟)**，每张约3.5秒。时间分布：

| 步骤 | 耗时 | 占比 | 说明 |
|------|------|------|------|
| `image::open(src)` | ~3000ms | **85%** | 🔴 主要瓶颈：解码WebP图片 |
| `create_thumbnail` | ~520ms | 15% | 缩略图生成（含resize） |
| `std::fs::copy` | ~1ms | 0% | 文件复制（极快） |
| `save_as_jpg` | ~14ms | 0% | 缩略图保存（极快） |
| DB插入 | ~1ms | 0% | 数据库操作（极快） |
| 解析时间戳 | ~27ms | 1% | 正则匹配（可优化） |

### 根本原因

1. **`image::open()` 对 WebP 解码极慢**：Rust 的 `image` crate 对 WebP 格式的解码性能很差（纯 Rust 实现，无 SIMD 优化）。一张 4K WebP 截图解码需要 3 秒，这是不正常的——同等大小的 PNG/JPG 解码通常只需 50-200ms。

2. **缩略图生成慢**：`image.thumbnail()` 虽然使用了快速降采样，但在大图上仍需 500ms。

3. **串行处理**：40张图片逐个处理，无法利用多核CPU。

4. **正则编译开销**：`parse_filename_timestamp` 每次调用都重新编译正则表达式。

5. **不必要的全量解码**：仅为生成缩略图就需要将整张图片解码到内存，对于大图（如4K截图）非常浪费。

## 优化方案

### 方案1：快速导入 + 后台缩略图（推荐，核心方案）

**核心思路**：导入时只复制文件和插入数据库记录，缩略图生成推迟到后台异步执行。

**实现步骤**：

1. **修改 `process_and_save_image`**：导入时跳过 `image::open()` 和缩略图生成，仅执行 `fs::copy`
2. **新增 `generate_thumbnail_async` 命令**：后台逐个生成缩略图
3. **修改前端**：导入完成后立即关闭进度弹窗，显示截图列表（使用占位图或原图），缩略图在后台慢慢生成替换
4. **修改缩略图加载逻辑**：如果缩略图文件不存在，显示占位图（灰色背景+图标），并在后台触发生成

**预期效果**：导入40张截图从 138秒 → **约2-3秒**（仅文件复制+DB插入）

### 方案2：使用外部工具解码 WebP（性能提升）

**核心思路**：使用系统 libwebp 或 Windows WIC 解码 WebP，比纯 Rust 实现快 10-50 倍。

**实现步骤**：

1. **使用 `windows` crate 调用 WIC (Windows Imaging Component)**：Windows 原生图片解码，支持硬件加速
2. 或使用 `libwebp` C 库绑定（通过 `libwebp-sys` crate）

**预期效果**：WebP 解码从 3000ms → **50-200ms**

### 方案3：并行处理（辅助优化）

**核心思路**：使用多线程并行处理多个文件的缩略图生成。

**实现步骤**：

1. 使用 `rayon` 或手动线程池并行处理
2. 注意数据库锁的竞争问题

**预期效果**：4核CPU上约 3-4 倍提速

### 方案4：小优化（立即可做）

1. **缓存正则表达式**：使用 `lazy_static!` 或 `once_cell::sync::Lazy` 预编译正则，避免每次调用重新编译（节省 ~27ms/文件）
2. **批量数据库插入**：将逐条插入改为事务批量插入
3. **避免重复查询已有文件名**：当前每次导入都查全表，可优化

## 最终实施计划（方案1 + 方案4）

### Step 1: 修改 `process_and_save_image` 为快速模式

文件：`src-tauri/src/main.rs`

- 新增 `process_and_save_image_fast` 函数，仅执行文件复制，不生成缩略图
- 修改 `import_screenshots` 使用快速模式
- 缩略图路径仍然记录到数据库，但文件暂不创建

### Step 2: 新增后台缩略图生成命令

文件：`src-tauri/src/main.rs`

- 新增 `generate_thumbnails` Tauri 命令
- 接收游戏ID和截图ID列表
- 在后台线程逐个生成缩略图
- 通过事件通知前端缩略图生成进度

### Step 3: 修改前端导入流程

文件：`src/App.jsx`

- 导入完成后立即刷新截图列表（不等待缩略图）
- 导入完成后自动触发后台缩略图生成

### Step 4: 修改缩略图显示逻辑

文件：`src/components/ScreenshotGrid.jsx`, `src/components/GameDetail.jsx`

- 缩略图文件不存在时显示占位图（灰色背景 + 图片图标）
- 监听缩略图生成事件，动态替换占位图为真实缩略图

### Step 5: 正则预编译 + 批量DB插入

文件：`src-tauri/src/main.rs`, `src-tauri/src/database.rs`

- 使用 `once_cell::sync::Lazy` 预编译正则表达式
- 导入时使用事务批量插入数据库记录

### Step 6: 验证构建

- 前端 `npm run build`
- 后端 `cargo check`
